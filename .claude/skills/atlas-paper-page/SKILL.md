# llm-atlas 论文介绍页规范

为 llm-atlas（VitePress 中文知识库）新增**单篇论文介绍页**时，按本规范产出。目标读者：中文工程师；页面价值在于"中文 + 有谱系 + 带原图"的二次梳理，而非翻译 abstract。

## 0. 准备：读论文、定槽位

1. 用 WebFetch 抓 arXiv **PDF**（`https://arxiv.org/pdf/<id>`）。结果会把 PDF 存到本地一个 `tool-results/*.pdf`，**记下这个路径**（抽图要用）。再用 Read 的 `pages` 参数通读全文，提取：全称、作者机构、年月、代码仓库、abstract 原文、动机、创新点、方法细节、实验数字、关键图表编号。
2. 确定页面归属章节与文件路径（如 `docs/agent/deep-research/<slug>.md`、`docs/skills/autoskill/<slug>.md`）。slug 用小写短横线。
3. 默认只做**中文版**；EN 目录只在该子章节已有英文镜像时才补。

## 1. 头部块（顺序固定）

```markdown
---
title: <中文描述性标题：名称（机构）：一句话定位>
---

# <同上中文标题>

**📄 [<英文论文全称>](https://arxiv.org/abs/<id>)**

<YYYY-MM> · <机构> · [代码](<repo URL，没有就省略整个· 代码>)

**一句话**：<1–2 句。讲"是谁 / 解决什么 / 关键差异"。不堆指标——数字一律下沉到「实验结果」。>

::: details 📖 论文原文 Abstract（英文）
<粘贴 abstract 原文；关键方法名可 **加粗** 或 *斜体*。>
:::

**相关**：<总览页> · <兄弟页1> · <兄弟页2> · …

![<Figure 1 的中文说明，写清左/右子图各画了什么>](/papers/<slug>/eval.png)

> 图源：<作者/团队>, *<论文名>*（arXiv:<id>）Figure 1——<一句话说明>（用于学习注解，版权归原作者）。
```

规则：
- **论文全称本身就是去 arXiv 的超链接**，不再单列 "arXiv:xxxx" 文字。
- 头部只留**机构 + 提出时间 + 代码**；不放 arXiv 号、不放 benchmark 数字。
- **相关放在 Abstract 折叠块下面**，且 `相关` 下面紧跟**论文第一张图（Figure 1）**——第一张图通常是全文最重要的总览/结果图，放开头。
- **不写「参考文献」整节**（单篇论文页冗余）：论文链接=标题，代码=头部，基准/底座/数据集在正文里已出现。

## 2. 章节骨架（四个固定 H2 + 描述性副标）

顶级 H2 固定这四个，**带描述性副标**（右侧目录已配置自动加宽/换行，副标可长）：

```markdown
## 动机与创新点：<副标>
<动机：现有方法缺什么、为什么这么做>，然后一段 **关键创新** 的 bullet 列表逐条点出贡献。
（动机与创新点合并一节，别拆成两个薄 H2。）

## 方法：<副标>
### <描述性子标题1>
### <描述性子标题2>
…（方法的各模块降为 H3；右侧目录 level 2–3 都显示）

## 实验结果：<副标>
### <自建基准 / 评测设置>（若有）
### Benchmark 表现
<表格 + 末尾一句"看榜须知"：口径/时点/工具配置各异，跨系统比绝对值意义有限。>

## 在 <X> 谱系里的位置
<与同类工作横向对比（vs A / vs B），这是本站相对 arXiv 的核心增值，务必保留。>
```

## 3. 方法页质量要求（重点）

没读过论文的人，读完「方法」要能讲清这篇怎么做。每个 H3 子模块：

- **讲机制 + 讲动机**：不仅"做了什么"，还要"为什么这么做、解决什么"。
- **加具体例子**：抽象机制配一个 `> 举例：…` 说明（如逆向工程造数据、知识图谱多跳模糊化、奖励二值化映射各举一例）。
- **多引用论文原文**：关键论断穿插**英文原文**（短句用引号 `"..."`、整句用 blockquote `>`），再用中文解释。公式（如目标函数）用 `$...$` / `$$...$$` 照搬。
- 能用 `mermaid` 画流程/架构图就画（流水线、循环、多 agent 协作）。

## 4. 嵌入论文原图（必做）

方法/结果都应配论文原图。流程：

1. **渲染页面**：`pdftoppm -png -r 150 -f <页码> -l <页码> <本地PDF路径> <scratchpad>/page<页码>`（150 DPI，US Letter 输出约 1241×1754）。
2. **定位并裁剪**：先 Read 渲染出的整页 PNG 找到图的像素区域，再用 Python PIL 裁：
   ```python
   from PIL import Image
   Image.open('pageN-0N.png').crop((x0, y0, x1, y1)).save('figX.png')
   ```
   裁完 **Read 一遍裁剪结果**核对（别裁进 caption / 别切掉坐标轴），不对就调坐标重裁。
3. **落盘**：`cp figX.png docs/public/papers/<slug>/<name>.png`（目录 `mkdir -p`）。
4. **嵌入**（markdown 里用 `/papers/...` 绝对路径，对应 `docs/public/papers/...`）：
   ```markdown
   ![<中文 alt：这张图说明了什么>](/papers/<slug>/<name>.png)

   > 图源：<作者>, *<论文名>*（arXiv:<id>）Figure N——<说明>（用于学习注解，版权归原作者）。
   ```
   **每张图都要带"版权归原作者"的图源注脚。**
5. **放哪**：Figure 1 → 开头（相关下面）；其余图放到对应的方法/实验子节旁（如系统架构图→系统架构节、训练曲线→训练节）。

## 5. 注册到导航与索引

- **侧栏**：在 `docs/.vitepress/config/zh.ts` 对应章节的 `items` 里加一行 `{ text: '<名称（机构）>', link: '/<path>/<slug>' }`，插到时间顺序合适的位置。
- **章节总览 `index.md`**：通常要更新四处——①分类对比大表加一行；②演进时间线加节点；③对应小节的 bullet 列表加一条（含"详见 XX 专页"）；④参考链接/文献加一条。
- 跨页引用尽量用**正文内联链接**（提到 PPO/某基准/某兄弟工作时就地挂链接），比堆"相关"列表更有用。

## 6. 风格基线

- 语气与既有页一致：开门见山、有 mermaid、有表格、有"务实的边界/局限"。
- 数字一律标注"以原文为准"；跨系统分数加"看榜须知"。
- 布局/CSS 是全局配置（`docs/.vitepress/theme/custom.css` 已处理正文宽度、右侧目录加宽换行、侧栏/nav 对齐），**写页时无需也不要改 CSS**。

## 参考样板

`docs/agent/deep-research/step-deepresearch.md` 是按本规范做的完整样板（头部块、四段骨架、详细方法+原文引用+例子、4 张论文原图、谱系节）。新页对照它即可。
